## Objective

> Implement **keywright** per `docs/plans/overview.md`: a cross-platform (Windows/macOS/Linux), reference-oriented credential lifecycle helper for coding agents and Kubernetes — compiled Rust broker, human CLI, and agent-facing MCP adapter — where the agent discovers credential requirements and orchestrates approved provisioning/rotation without receiving plaintext credentials or unrestricted crypto authority. Vault stays out of scope.

## Current state
Greenfield repo: `Cargo.toml` (deps: age 0.12, axum 0.8, kube 4.2 / k8s-openapi v1_34, openssl vendored, tokio-openssl, proptest), stub `src/main.rs`, and `docs/plans/overview.md`. Nothing implemented yet.

## Decisions (design doc + interview)
1. **Cargo workspace**: `crates/core` (policy engine, rotation state machine, encrypted storage, signing-provider abstraction), `crates/broker` (privileged axum HTTPS server, mandatory mTLS), `crates/cli` (human CLI incl. install/enroll/approve/import), `crates/mcp` (stdio MCP adapter via official `rmcp` crate). Rejected: single-crate/3-binaries (no structural trust separation).
2. **Topology**: Pi agent → stdio MCP adapter (own low-priv agent client cert) → mTLS HTTPS loopback broker. Compilation is packaging, not a security boundary.
3. **Approval model**: ACME-style conditional auto-approval — policy rules auto-approve when client cert, profile, destination, and conditions match; unmatched privileged ops return PENDING_APPROVAL with a stable operation id; human fallback via `keywright approve <op-id>` under a separate admin client cert. Requester ≠ approver enforced.
4. **Storage**: broker-owned data dir under a dedicated OS service account (`/var/lib/keywright` or `C:\ProgramData\keywright`), OS ACLs denying the agent's user write access. SOPS-encrypted records via pinned external sops executable invoked without a shell, age recipients (Rust age lib for age-native needs; no outer rage layer). No native SOPS fallback — missing/stale binary = explicit FAILED + dependency report. Atomic encrypted-record replacement + encrypted version retention.
5. **Service installation ships**: `keywright install` registers systemd/launchd/Windows service, creates the service-account data dir + ACLs, and generates an age-protected built-in transport CA. `keywright enroll --role agent|admin` (human-run) issues client certs; revocation via broker denylist + config ACL; transport-credential recovery path included.
6. **Broker K8s identity**: dedicated kubeconfig pinned in broker config (approved clusters/namespaces only; never inherits caller context). Direct kube API client (no kubectl shell-out). Namespace-scoped RBAC; no namespace creation/workload mutation/secret deletion/RBAC admin.
7. **Renewal**: broker-internal scheduler (daily expiry scan) drives the same rotation state machine with no agent session required. Failed

## Verification contract

credential.list/describe/ensure, rotation.plan/execute/status/abort, certificate.inspect/ensure/rotate. Outcomes: READY, PENDING_APPROVAL, NEEDS_HUMAN_IMPORT, CONFLICT, DENIED, FAILED. Metadata-only responses; stable request/operation ids. Agent-supplied paths/URLs/commands/issuer configs untrusted; references resolved through broker-controlled mappings.
9. **Certificates**: profiles (constrained SANs/EKUs/algorithms/validity/issuer), application keys distinct from issuer signing keys, software-backed test CA for initial release, PKCS#11 extensibility via a tested signing-provider trait. Renewal and rekey modeled separately. No arbitrary raw signing.
10. **State machine**: durable resumable PLANNED → APPROVED → PREPARED → DEPLOYED → VERIFIED → RETIRED with idempotency keys, per-credential locking, expected-version checks, approval bound to resolved plan/version/privileges/destinations, external-issuance reconciliation, abort/rollback/revocation distinguished.
11. **Security controls per doc**: mTLS-only privileged endpoints (no unauthenticated fallback), loopback default, agent-vs-human permission separation, immediate client-identity disabling, plaintext never in argv/logs/audit/temp files, sanitized subprocess env, audit trail, separate encryption-identity backup + tested recovery.

## Out of scope (initial release)
Vault, arbitrary signing APIs, exporting non-exportable keystore keys, universal token-issuer integrations, production root-CA administration, general-purpose K8s deployment system, PKCS#11 hardware integration (trait + software-backed test provider only).

## Milestones (each independently verifiable)
1. **Workspace scaffold + core types + CI**: cargo workspace with 4 crates, CI workflow (3-OS build/test/clippy/fmt matrix), core domain types (credential refs, versions, lifecycle states, operation ids, outcome enum) with unit tests.
2. **Transport trust**: install command (service account, data dir + ACLs, service units for all 3 OSes), built-in transport CA, enroll (agent/admin certs), mTLS-only axum server with client-cert identity → role mapping, denylist, transport-credential recovery.
3. **Inventory + policy + auto-approval**: credential.list/describe (metadata-only), policy engine with conditional auto-approval rules, PENDING_APPROVAL records, `keywright approve`, agent≠approver enforcement, NEEDS_HUMAN_IMPORT flow + `keywright import` trusted path.
4. **Persistence + K8s delivery**: SOPS-encrypted storage via pinned binary (age recipients), atomic replacement + version retention, direct kube client with pinned clusters/namespaces/generic + TLS Secret delivery, ensure-without-overwrite idempotency.
5. **Rotation engine**: durable state machine with idempotency/locking/expected-version, approved-plan binding, order-controlled producer/consumer updates, broker-controlled verification, overlap-period retirement, abort/rollback/revocation, crash-injection recovery, concurrent/stale-version safety, broker-internal renewal scheduler.
6. **Certificates**: application key gen, CSR signed by application key, software-backed test CA issuer via signing-provider trait, profile validation, cert/key match + chain validation, matching pair delivered to K8s TLS Secret, renewal vs rekey separately tested, external-issuance reconciliation.
7. **MCP adapter + Pi integration**: rmcp-based stdio adapter exposing the 10 operations with structured outcomes, Pi integration guidance (agent config example, enrollment walkthrough).
8. **Demos + security-boundary tests + docs**: three scripted end-to-end gates against the homelab cluster (or vcluster/kind fallback) with stand-in consumer workloads in `keywright-demo-*` namespaces — RustFS: local cred gen/idempotent ensure/verified rotation; Matrix: human import → Secret delivery without agent exposure; TLS: key/CSR/issue/deliver/verify + renewal/rekey — plus negative security tests (unauthorized client, self-approval, wrong namespace, plaintext leakage scans) and documentation (install, enrollment, policy examples, Pi integration, rotation recovery, backup restore, limitations).

## Risks & failure modes
- Homelab cluster unreachability blocks K8s integration gates → vcluster/kind-on-WSL2 fallback; integration tests tagged ignored-by-default, runnable on demand.
- Pinned sops binary absence/staleness → explicit FAILED with dependency report (no silent native fallback).
- Windows service/ACL semantics differ per OS → per-platform install tests; ACL code isolated per platform.
- rmcp API churn → pin version; adapter stays a thin mapping layer.
- Rotation mid-flight crash → crash-injection tests at every state boundary; resume via durable records; never auto-revoke working creds.
- Agent-compromised adapter → agent cert is low-priv; broker enforces policy/destination pinning; immediate identity disable.
